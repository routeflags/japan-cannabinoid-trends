# methodology — x-26week-trends

## 1. 研究設計

CBX リキッドという特定キーワードの X (Twitter) 上での
**言及量の時間的推移**を把握する記述的（descriptive）調査。
介入・対照の概念はなく、単一キーワードの週次系列を観察する。

| 項目 | 値 |
|------|-----|
| 研究質問 | CBX リキッドへの X 上の言及はいつ・どのように現れ、増えたか |
| 観察単位 | 週（週次窓、`since:`/`until:` で区切る） |
| 観察期間 | 2026-03-19 〜 2026-09-17（26 週） |
| キーワード | `CBX リキッド`（日本語） |

## 2. 収集手順

- **ツール**: Apify Actor `cPYLH3QT9GyzKhB4S`（patient_discovery/twitter-search）
- **検索式**: `CBX リキッド since:YYYY-MM-DD until:YYYY-MM-DD`
- **section**: `latest`（投稿日時降順）
- **maxPages**: `5`（1 週あたり最大約 100 件）
- **実行主体**: 旧ワークスペース `projects/ec/research/20260917/` の
  `cbx_x_26week_collector.sh`（リポジトリ外。計画書 §4.2 に記載）

計画書は全週 100 件取得時の上限を見込んでいたが、実際の取得は総 251 件。

## 3. 前処理・重複排除

- **重複排除**: `tweet_id` ベース（総取得 251 件 → 231 件）
- **投稿日時フィルタ**: 対象期間内の投稿のみを残す
- raw レコードの保管場所は本リポジトリ外
  （[README の raw データについて](./README.md#raw-データについて重要)参照）。
  重複排除は取得時または直後の分析段階で実施されたものであり、
  本リポジトリからは intermediate な生レコードを追跡できない

## 4. 分集計

- **週次集計**: 各週の投稿件数・累計（レポート §2）
- **月次集計**: 週次系列からの再集計（レポート §3）
- **上位投稿者**: screen_name 単位の件数集計（レポート §4.3）

集計はレポート作成時の手作業またはスプレッドシートベースであり、
再現用スクリプトは本リポジトリに保存されていない
（PROVENANCE INCOMPLETE: 集計段階の再現コードは未収蔵）。

## 5. 制限事項

1. **raw 未収蔵**: 生レコードがリポジトリ外のため、
   集計値の再計算による検証は現状不可能
2. **サンプリング上限**: 週あたり最大約 100 件。
   実投稿数が上限を超えた週（例: W19 で 40 件は上限内）は全数に近いが、
   超過時は latest での切り捨てが発生しうる
3. **取得方式の非互換**: 旧来の日別 latest 取得
   （`datasets/cbx-social-trends` の 202608 データ等）とは
   クエリ方式が異なるため、単純な接続や比較には再考慮が必要
   （レポート §5）
4. **非決定的ソース**: X 検索結果は再実行で変化しうる
5. **記述にとどまる**: 7 月の急増と市場展開の時系列的並行は観察されるが、
   因果的主張は行わない

## 6. 再現性

- 計画書（`analysis/x_26week_trend_plan.md`）に検索式・週分割・
  取得上限が保存されており、**収集設計**は再現可能
- ただし raw レコードと集計コードがリポジトリ外のため、
  **数値結果の完全な再現は現状不可**
  （raw 収蔵 + 集計スクリプト保存により改善可能）
