# Issue: Request-only VCR（本文を記録しない取得証跡）と実行証跡の完全性が未実装

**ID:** ISS-20261015-PRV-033  
**優先度:** P2 (Medium)  
**ステータス:** OPEN  
**対象:** `ISS-20261015-COL-030` §5 / §7.1 / §8、保存先と追跡方針（`config/storage-policies.json`, `.gitignore`）、`metadata/provenance/evidence-registry.json`

## 概要

指示書は「取得手順・実行証跡を公開して第三者検証可能にする」ことを目的の中核に置くが（§1 / §7.1 /
§7.3）、その証跡を作る仕組みが無い。VCR.py 等を使う場合は**標準のレスポンス記録をそのまま使わない**
（本文・投稿 ID・`next_token` 原値を残さない）ことが明示されている。

## 確認された観測

- VCR / リクエストログ / 実行 ID / ログの SHA-256 を扱うコード・ファイルはリポジトリに存在しない。
- 公開可能な成果物（指示書 §4.3）に「APIリクエストの証跡（機密情報を除去したもの）」が含まれるが、
  証跡を置く保存層（`raw` / `interim` / `processed` 以外）や追跡方針は未定義。
  `ARTIFACT_LAYERS`（`src/validation/schemas/artifact.py`）は 3 層のみ。
- `metadata/provenance/evidence-registry.json` は既存の証跡参照の登録先だが、実行事跡の形式は
  定義されていない。

## 影響

- 指示書の完了条件のうち「Request-only VCRで取得証跡を生成できる」「レスポンス本文・認証情報が
  証跡に含まれない」「取得手順の再実行可能性」が満たせない。
- 証跡の保存先が未定のまま実装すると、無追跡・無分類のパスが増える（`ISS-20261015-AUD-028` と
  同型の罠）。

## 対応方針

- 記録項目は指示書 §5.2 の表を正本とする（保存 ○ / × をテストで固定）。
- §3.3 の「全ページの記録」と §5.2 の「`next_token` 原値 ×」の緊張は、**ページ番号 + トークンの
  ダイジェスト + 累計件数**で満たす（連続性・欠落検出に原値は不要）。
- 形式は JSON Lines、実行 ID で複数リクエストを関連付け、完了時に SHA-256 と取得コードの
  git commit を記録する。ハッシュは改変検出の補助であり真正性を単独保証しない旨を文書に残す（§5.3）。
- **保存層と追跡方針を先に決める**（公開可能な証跡なので層の追加か既存層への配置、
  `config/storage-policies.json` への方針追加、`.gitignore` の規則を 1 変更で揃える）。
- 公開前検査: 証跡にクエリ文字列・個人情報・再配布制限対象が混入しないことを自動検査する
  （既存の `scan_for_secrets` / `audit-x-identity` と規則を二重実装しない範囲で）。
- テスト: 本文混入防止・token 混入防止・ハッシュ生成・欠落検出（指示書 §8）。
