# Issue: 非公開 X データの保持・更新・削除（鮮度維持）の管理が無い

**ID:** ISS-20261015-PRV-036  
**優先度:** P2 (Medium)  
**ステータス:** OPEN  
**対象:** `ISS-20261015-COL-030` §4.2 / §10、`datasets/*/data/private/`（`.gitignore`）、保持・削除の記録先（未定）

## 概要

指示書 §4.2 は、取得した X データを「研究処理に必要な範囲でのみ利用」し、非公開領域での保持・
データ保持期間の管理・X の鮮度維持要件（投稿の削除・非公開化）への対応・保持できないデータの
削除・それらの履歴記録を要求する。現状は**非公開領域はあるが、管理の記録も手順も無い**。

## 確認された観測

- 非公開領域は存在する: `datasets/*/data/private/` は `.gitignore:51` で除外、
  `datasets/cbx-social-trends/data/private/` に既存の非公開 X 要約がある（内容は開かない）。
- 保持期間・更新頻度・削除の記録形式はリポジトリに存在しない。
- 指示書 §4.2 は「具体的な保持期間や更新頻度は、適用される X Developer Policy の条項を確認して
  設定する」とし、**実装者が数値を推測で決めることを禁止**している。

## 影響

- 規約上の保持・削除要件を満たしていることを第三者に示せない。
- 方針が未決定のまま実取得を進めると、保持が認められないデータを抱えることになる。

## 対応方針

- 決定を待ってから実装する（`ISS-20261015-COL-030` U1 = 保持期間 / 更新頻度）。
  決定までは「未決定であること」を文書に残し、数値を作らない。
- 決定後: 保持対象・期間・更新頻度・削除条件を機械可読な設定として持ち、
  「取得 → 保持 → 更新 → 削除」の履歴（日付・対象・理由・実行主体）を非公開領域に記録する。
- 削除は黙って消さない（削除記録を残す。AGENTS.md の「記録せずに消さない」原則に合わせる）。
- 保持・削除の記録が**公開物に漏れない**ことを検査の対象にする（非公開領域は追跡外）。

## オーナー回答（2026-10-15）

- PUB-029 の中間データは削除してよい。
- 集計は非公開元入力からスクリプトで再生成する。投稿単位の中間成果物は保持しない。
- 非公開元入力自体は改変しない。削除対象は、再生成可能な中間データであり、raw/元入力の黙示的な削除ではない。
