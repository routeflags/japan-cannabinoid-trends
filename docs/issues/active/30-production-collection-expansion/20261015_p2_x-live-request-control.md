# Issue: X API の live request 制御（件数上限・402/429/401/403）が無い

**ID:** ISS-20261015-COL-032  
**優先度:** P2 (Medium)
**ステータス:** OPEN  
**対象:** `ISS-20261015-COL-030` §3.4 / §8、X 用 adapter（`ISS-20261015-COL-031`）

## 概要

指示書 §3.4 は、X API の live request に事前の件数見積りと実行単位の取得件数の記録、
件数上限と到達停止を要求するが、現状のリポジトリには上限も停止規則も無い。
**上限なしで実取得を始めると止まらない**ため、移行本体より先に設計を確定する。

単価・予算額・請求額は扱わない（`AGENTS.md` Scope Exclusion: Cost）。

## 確認された観測

- 件数上限・停止規則を扱う記述はリポジトリに存在しない（実測: `X_BEARER_TOKEN`
  同様、関連の設定ファイルも無い）。
- 既存の collection core は「実行結果（status / returned_count / errors）」しか記録せず、
  件数上限の設定を持たない。
- 指示書 §3.4 の上限の**値は未定**。

## 影響

- 実取得試験（COL-031 の完了条件）を安全に実行できない。
- 取得件数の上限が未設定のまま実行経路が開くと、止まらない取得を停める手段がない。

## 対応方針

- **owner 決定（2026-10-15）:** 基盤がそろうまで X の live request は禁止し、リポジトリ内の
  実行経路は mock / dry-run に限定する。live 実行は、この issue と
  `ISS-20261015-PRV-033` の request-only evidence が通った後に、別途明示承認を要求する。
- 件数上限を**設定**として外出しする（リポジトリに置くのは構造と単位まで。値は環境設定。
  秘密情報は書かない）。owner 決定により当面の local / CI 既定上限は `0`
  （live request 拒否）として扱う。
- 実行前の見積り（クエリ・期間・上限件数 → 推定件数）を出力する dry-run を用意する。
- 実行単位で「取得件数 / ページ数 / 累計件数」を run の environment または実行証跡
  （`ISS-20261015-PRV-033`）に記録する。上限到達時は新規リクエストを停止（fail closed）。
- HTTP 402 / 429 / 401 / 403 を別状態として扱う（支払い要求・レート制限・認証失敗・権限不足を
  同じ「失敗」に潰さない）。既存の `CollectionResult.status` の語彙で表現できない場合は
  拡張を提案する（推測で記録しない）。
- テストはモックで行い、外部への実リクエストを発生させない（指示書 §8）。

## 完了条件

- [ ] 件数上限の設定スキーマと読み込み（未設定または local / CI 既定 `0` なら live 実取得を拒否）
- [ ] dry-run 見積りと実行単位の件数記録
- [ ] 上限到達時の停止が動作する（テストで固定）
- [ ] 402 / 429 / 401 / 403 の別状態処理とテスト
