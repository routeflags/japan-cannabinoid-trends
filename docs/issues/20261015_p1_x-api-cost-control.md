# Issue: X API の費用管理（従量課金・予算上限・402/429 処理）が無い

**ID:** ISS-20261015-COL-032  
**優先度:** P1 (High)  
**ステータス:** OPEN  
**対象:** `ISS-20261015-COL-030` §3.4 / §8、X 用 adapter（`ISS-20261015-COL-031`）、設定ファイル（課金単価・上限）

## 概要

指示書 §3.4 は X API の従量課金を前提に、事前見積り・単価の設定可能化・実行単位の件数と費用の
記録・予算上限と到達停止を要求するが、現状のリポジトリには課金の概念も上限の設定も無い。
**上限なしで実取得を始めると課金が止まらない**ため、移行本体より先に設計を確定する。

## 確認された観測

- 課金単価・予算上限・推定費用を扱う記述はリポジトリに存在しない（実測: `X_BEARER_TOKEN`
  同様、課金関連の設定ファイルも無い）。
- 既存の collection core は「実行結果（status / returned_count / errors）」しか記録せず、
  費用フィールドを持たない。
- 指示書 §3.4 は「課金単価はコードに固定せず設定可能にする」とし、単価・上限の**値は未定**。

## 影響

- 実取得試験（COL-031 の完了条件）を安全に実行できない。
- 費用が未記録のままデータだけが残ると、取得のコスト根拠を示せない（研究の再現性・
  説明責任に影響）。

## 対応方針

- 課金単価と予算上限を**設定**として外出しする（リポジトリに置くのは構造と単位まで。keys や
  実際の値は環境設定。秘密情報は書かない）。
- 実行前の見積り（クエリ・期間・上限件数 → 推定件数・推定費用）を出力する dry-run を用意する。
- 実行単位で「取得件数 / ページ数 / 累計件数 / 推定費用」を run の environment または実行証跡
  （`ISS-20261015-PRV-033`）に記録する。上限到達時は新規リクエストを停止（fail closed）。
- HTTP 402 / 429 / 401 / 403 を別状態として扱う（未使用クレジット・レート制限・認証失敗・権限不足を
  同じ「失敗」に潰さない）。既存の `CollectionResult.status` の語彙で表現できない場合は
  拡張を提案する（推測で記録しない）。
- テストはモックで行い、実課金を発生させない（指示書 §8）。

## 完了条件

- [ ] 単価・上限の設定スキーマと読み込み（値は設定側。未設定なら実取得を拒否）
- [ ] dry-run 見積りと実行単位の費用記録
- [ ] 上限到達時の停止が動作する（テストで固定）
- [ ] 402 / 429 / 401 / 403 の別状態処理とテスト
