# X収集Actorの仕様・出力検証

対象：`routeflags/japan-cannabinoid-trends`

使用Actor：`patient_discovery/twitter-search`

## 目的

統計的サンプリング設計に先立ち、Actorの検索順序、期間指定、ページネーション、出力内容、再現性、網羅性の制約を特定する。

## Phase 1：既存データ監査

1. 既存のX Rawデータ、収集ログ、Run Metadataを調査する。
2. 各実行の検索クエリ、`section`、`maxPages`、取得件数を抽出する。
3. 投稿日時を取得順に比較し、単調減少しているか検証する。
4. 投稿IDの重複率と、検索期間外の投稿の有無を調査する。
5. 公開済みのActor仕様と、実際に使用したバージョンを照合する。

## Phase 2：追加PoC

既存データだけで判定できない場合に実施する。

- 同一クエリの再実行
- `maxPages=1` と `maxPages=3` の比較
- 過去の日付範囲指定
- 時刻指定の動作確認
- 取得結果の重複・欠落・並び順の比較

追加API費用が発生する実行は、事前に件数と費用を見積もり、ユーザーの承認を得る。

## Phase 3：報告

以下を表形式で報告する。

- 検証項目
- 公式仕様
- 実測結果
- 判定（PASS / FAIL / UNKNOWN）
- 証拠となるRun ID
- 研究設計への影響

## 制約

- 現段階では月間取得上限を決定しない。
- ランダムサンプリングを実装しない。
- Rawデータを変更しない。
- 取得できなかった投稿を0件と判断しない。
- 推測を実測結果として報告しない。

## 最終判断

次の3点を結論として示す。

1. このActorは、指定時間窓からの確率的サンプリングに使用できるか。
2. 月次投稿量を統計的に推定できるだけの取得完全性があるか。
3. 使用できない場合、Actor変更または研究指標の変更が必要か。
