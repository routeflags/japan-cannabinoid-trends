# ドメイン用語集（Glossary）

**版:** 0.1.0（草案、2026-10-16）  
**正本:** 定義は `docs/specs/contracts.md` §2・§2.1・§3.1 の引用。本ファイルは DDD 導入のための写しであり、定義の変更は contracts.md 側で行う。  
**選定:** owner 選定キーワード 4 件（生産・研究・加工・契約、2026-10-16）。

| 用語 | 定義 | コンテキスト | 出典 | 曖昧さ |
|---|---|---|---|---|
| 生産 Production | パイプライン。上流の入力から契約準拠の記録（run / artifact / 加工成果物 / 生成値）を産出する側（収集・加工）。判定はしない | 生産 | `contracts.md` §2、§3.1 | コード名「パイプライン」との使い分け（パイプライン＝実装名、生産＝ドメイン名、§3.1）。台帳 `owner` の値には使わない（下位名 `collection` / `processing` のまま、§3.2） |
| 研究 Study | 研究質問・対象範囲・入力証拠・処理方法・成果物・制約を 1 つに束ねる研究単位。`study_id` で識別し `datasets/<study-id>/` に配置する。HTML ページや release ではなく dataset release の根拠になる研究集約 | 研究 | `contracts.md` §2、§2.1 | 日常語の「研究活動」一般との混同。transformation 来歴・evidence・measurement / research view を含む（§2.1） |
| 加工 Processing | 派生成果物の導出宣言と生成値。生産の下位コンテキスト | 加工（生産の下位） | `contracts.md` §2.1、§3.1 | 上位の生産との包含関係（生産を選ぶと加工は包含扱い）。実装は `src/processing/` |
| 契約 Contract | 境界を越えて渡されるデータ／振る舞いについて、版を持ち機械検証可能な形で宣言した合意。下位にスキーマ契約・レジストリ文書・インターフェース契約・ゲート契約・判断記録を含む総称 | 検証（総称の所有） | `contracts.md` §2 | 総称としてのみ使う（個別文書名には使わない。例：`collection-run-v1` であって `collection-run契約` ではない）。版・宣言場所・検査は下位種別ごとに異なる（§2表）。ゲート契約はその一種（段階遷移の可否判定、所有：検証・研究、版は未宣言＝既知ギャップG1、§10） |

## 備考（確立済み規則の引用）

- 生産は判定しない／検証は産出しない／生産の出力は記録であって解釈ではない（`contracts.md` §3.1 規則 1–3）。
